# 批量推理结果查看与评估设计

本文作为 Flowork 内部开发与验收依据，记录批量结果表格和 Python 批量评估的设计。目标是复用已有 workflow 批量执行、Task、结果文件和执行详情，让用户先观察结果，再计算指标、定位问题样本。本期功能已实现并部署；设计范围、实际限制和验收记录如下。

## 范围与原则

覆盖 workflow 页面批量执行、batch task 创建、batch task 详情、结果查看页面，以及 Task CLI。沿用已有批量执行链路，不增加独立数据集或实验管理产品，也不改变单节点执行、定时任务和 Deployment 的行为。

先实现结果查看与样本执行追踪，再接入自动和手动评估。评估直接消费已保存的结果，不重新执行 workflow。

## 结果查看入口

Batch run 详情页 Download 旁的 View in Storage 改为 View Result。按钮始终展示，执行期间不可用；推理结束且结果文件已完整写入后可用。

| 状态 | View Result 行为 |
| --- | --- |
| 排队、执行、等待人工审批、恢复执行 | 不可用 |
| 正常结束，包括部分样本执行错误 | 结果文件就绪后可用 |
| 取消、中断或失败，但已保存部分结果 | 可用，页面明确标注部分结果 |
| 没有结果文件 | 不可用，展示原因 |
| 推理已结束，评估仍在执行或评估失败 | 可用 |

点击后进入独立的只读结果表格页。页面包含任务名称、结果条数、成功和错误统计、搜索、筛选及下载入口。部分结果的统计只针对实际已有结果，不能冒充全部输入的最终统计。

表格展示样本序号、状态、Trace ID、输入、输出、错误和耗时，支持排序、列筛选、列宽调整、固定列及列显示选择。长文本或嵌套 JSON 在单元格中摘要显示，可展开查看完整内容。中英文界面均需适配。

## 表格组件与数据来源

采用项目已有的 AG Grid Community，复用现有样式和主题。只使用社区版能力，不引入商业授权依赖。搜索和筛选必须针对完整结果集，不能只搜索当前加载的页面；数据量较大时通过后端分页、过滤和排序加载。

规范数据源为批量执行保存的原始 JSONL。展示及评估均保留数字、布尔值、对象等类型，不能从格式化 CSV 反向解析。用户配置的导出列不应导致评估丢失原始数据。

当前批量结果包含样本索引、状态、原始输入、映射输入、输出、错误、耗时等信息。已有 execution_id 和 execution_url 可用于执行详情跳转。实际字段契约须在实现时与现有接口保持一致，尤其 output 可能是节点输出映射，不能默认当作单个 End 节点的值。

## Trace ID 与执行详情

Trace ID 展示样本的 execution_id，跳转到 `/workflow-executions/{execution_id}`，使用已有只读 workflow 执行画布及历史节点结果。该字段不是额外生成的链路追踪 UUID。

没有实际开始执行的样本不生成虚假的执行链接。恢复批量任务时，复用成功样本的结果也应保留其原始执行 ID。结果、下载和执行详情均沿用现有资源权限，不能仅凭任务 ID 或 Trace ID 绕过权限。

## 自动评估配置

在 workflow 批量执行页面及批量任务创建页面增加“推理结束后评估”，默认不勾选。勾选后显示 Python 代码编辑器，灰色 placeholder 展示模板函数；placeholder 不属于真实代码。可提供“使用模板”操作填入代码。开启评估但代码为空时，不允许提交。

评估函数接收整个结果列表，一次调用返回指标字典：

```python
def evaluate(results: list[dict]) -> dict:
    total = len(results)
    succeeded = sum(1 for row in results if row.get("status") == "success")
    return {
        "total": total,
        "execution_success_rate": succeeded / total if total else None,
    }
```

此模板仅说明接口，执行成功率不等于业务质量。业务指标由用户结合结果中的输入、输出及参考答案自行计算。

输入包含成功和失败样本，由脚本决定是否过滤和如何计算分母。返回值必须是可 JSON 序列化的字典；异常、非字典返回值及非法 JSON 值应给出可理解的错误。空列表也遵守相同接口。

本期交互式结果查看和评估限制原始结果文件不超过 32 MiB，评估进程内存上限 256 MiB、CPU 时间 20 秒、墙钟时间 30 秒，指标 JSON 上限 64 KiB、脚本上限 65536 字符。超限应明确报错，原有下载仍可用。

不允许导入第三方库。可使用内置函数以及明确允许的标准库，例如 math、statistics、collections。执行必须使用隔离环境和独立进程，限制运行时间、内存及输出体积，不能在 API 进程内直接执行用户代码。仅限制 import 不能作为安全隔离措施，评估不应获得宿主机凭据、其他任务文件或不必要的网络访问权限。

## Evaluation 页面

批量任务详情增加 Evaluation tab，统一管理评估脚本和评估结果。支持查看和修改脚本、保存配置、手动执行评估、查看状态、指标及错误。

创建任务时的配置与详情页使用同一份配置。自动和手动评估使用同一执行链路。每次评估记录至少包含执行时间、状态、脚本快照、输入结果版本、指标或错误；修改脚本不覆盖历史指标，重新评估产生新记录。

推理状态与评估状态分开。评估失败不会把已经完成的推理标记为失败；评估运行期间仍可查看和下载推理结果。同一任务的重复评估提交需要防重，避免反复点击导致重复执行。

自动评估在推理结果持久化完成后触发。正常完成但有错误样本的批量任务仍自动评估。取消或中断的部分结果先支持用户手动评估，并明确说明数据不完整。

批量恢复执行可能更新结果文件，因此评估必须绑定确定的结果内容版本，不能只记录可被覆盖的文件路径。旧评估保留其对应的数据版本信息，不应被展示为最新结果的指标。

## 存储与权限

复用现有结果文件存储、任务数据库和后台执行基础设施，不为本功能单独引入额外服务。评估配置和评估记录需要持久化，浏览器刷新后仍可查看。

查看结果、读取脚本、修改配置、发起评估和读取评估记录均进行现有租户与资源权限检查。读权限不应自动授予修改或执行权限。后台工作使用与任务一致的授权边界，返回错误时不得泄露内部凭据和宿主路径。

评估读取的结果版本必须稳定，避免恢复执行覆盖文件时产生混合输入。记录和结果不新增自动清理策略，沿用任务现有生命周期。

## Task CLI

创建批量任务时支持通过 `--evaluation-script eval.py` 指定脚本，上传脚本内容而非宿主文件路径。提供 `task evaluation-config` 保存脚本与自动评估开关、`task evaluate` 发起手动评估、`task evaluation` 查询状态及历史指标。三者均显式指定 `--task_type batch_exec --task_id ID`；配置命令使用 `--evaluation-script eval.py`，可选 `--auto-evaluate true|false`。排队成功的 CLI 命令返回退出码 0，但不代表评估已完成。

同步更新参数校验、帮助文本、CLI 使用说明及 Agent 可见的相关说明。网页和 CLI 使用相同的服务接口及权限检查。

## 实现顺序

1. 结果读取接口、View Result 入口、专业表格页面及 Trace ID 跳转。
2. 评估持久化、隔离执行、自动触发和手动接口。
3. 两处创建页面配置、Evaluation tab、CLI 及说明。
4. 自动化验证、真实服务部署与验收，审查变更后提交代码。

## 验收要求

必须在真实服务中部署并使用账号完成验收；不能仅凭单元测试或构建通过判断完成。不进行压力测试。以下情况全部符合预期后，才能标记需求完成。

- 执行期间结果按钮不可用；结束后可打开结果；无文件、失败、取消及部分结果的行为符合状态表。
- 表格的搜索、筛选、排序、长文本和 JSON 查看、中英文布局正常，操作范围覆盖完整结果。
- Trace ID 能打开对应样本的历史执行画布；成功、失败及恢复复用的样本均对应正确；未执行样本无假链接。
- workflow 批量入口和 Task 创建入口默认关闭评估；打开后显示编辑器；空脚本校验与模板操作正常。
- 自动评估仅在结果就绪后执行，输入数据和类型准确，错误样本及空输入处理符合函数契约。
- Evaluation 页面支持配置、手动执行、状态、指标、错误及历史记录；刷新后仍可查看。
- 脚本异常、语法错误、非字典返回、第三方库导入、超时和资源限制可控，推理结果不受影响。
- 部分结果可手动评估；批量恢复后结果版本明确，历史评估不冒充最新指标；重复提交得到明确处理。
- CLI 完成脚本指定、配置、触发和查询，与网页行为一致。
- 未认证和无权限访问不能读取结果、执行详情、脚本或评估记录，也不能修改配置和触发评估。
- 保留原有批量执行、下载格式、自定义输出列、恢复执行和人工审批能力。

实际验收记录应注明部署版本、测试场景、结果及尚未解决的问题，不把尚未验证的目标写成已完成。

## 实现接口与存储

- `POST /api/v1/tasks/{task_id}/results/query`：分页查询原始结果，支持 search、row_status、列 contains 筛选、排序和 offset/limit；返回筛选后的总数、全量状态统计及结果内容哈希。页大小最多 500。
- `GET /api/v1/tasks/{task_id}/evaluation`：读取配置、评估历史、结果版本和可评估状态，需要 Task view 权限。
- `PUT /api/v1/tasks/{task_id}/evaluation`：保存 enabled 和 script，需要 Task update 权限。
- `POST /api/v1/tasks/{task_id}/evaluation`：需要 Task execute 权限；成功排队返回 HTTP 202，已有评估或推理未结束返回 HTTP 409。
- 配置和历史保存在 Task 已有的加密 payload 中；结果摘要增加 result_version。后台队列只传递 task_id 和 evaluation_id，不传脚本、样本或指标。无需新增数据库表或外部组件。
- 评估使用独立沙盒作用域，关闭网络和用户文件挂载。Task 行锁协调评估提交、恢复与删除；已有评估排队或执行时，恢复与删除返回冲突。

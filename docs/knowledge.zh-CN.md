# 知识资料包

Knowledge 以带版本的文件资料包保存可复用笔记和参考资料。每个资料包都是普通目录树，而不是平台专有的索引格式，因此用户与 Agent 看到的是同一份源文件。

## 资料包结构

每个资料包的根目录都必须包含 `README.md`。README 应说明资料包的用途和范围、概括目录结构，并解释重要文件的作用。除此之外，子目录和文件名可由用户自行组织。资料包可包含文本、源码、PDF、Office 文档、图片、音频、视频以及其它相关文件。

例如：

```text
agent-evaluation/
├── README.md
├── notes/
│   ├── evaluation-methods.md
│   └── open-questions.md
├── sources/
│   ├── benchmark-paper.pdf
│   └── framework-comparison.xlsx
└── media/
    └── architecture.png
```

原始文件是权威数据。即使所有文件都没有建立索引，资料包仍然可以正常使用。只有在检索确有帮助时，平台才会按文件类型生成可丢弃的派生视图，例如对 Markdown 按章节提取、对 PDF 保留页码信息，或不为不透明的二进制文件建立文本索引。这些派生内容不会取代或改变资料包中的文件。

因此，Web 应用会把资料包直接展示为文件浏览器：用户从左侧目录树选择文件，在右侧阅读原始内容。索引维护由系统自动完成，不属于普通用户的操作流程。

右侧内容区会根据文件本身选择合适的展示方式：Markdown 使用文档式阅读排版，源码提供语法高亮、行号与代码折叠，图片、音频、视频和 PDF 使用对应的原生浏览界面。Office 文档及暂不支持浏览的二进制格式会明确显示文件类型并提供下载，不会被错误地当成普通文本展示。

使用“上传资料”可以从一个完整的本地文件夹或 ZIP 压缩包创建资料包。导入器会保留嵌套目录，允许传输时额外包裹一层文件夹，并在创建任何内容之前确认逻辑根目录存在 `README.md`。路径穿越、重复路径、加密或非普通 ZIP 条目、超大文件及超大资料包都会被拒绝。

进入资料包后，可以右键文件树（触屏设备使用“文件操作”菜单）上传文件或文件夹。右键文件夹可向该位置上传内容或删除文件夹，右键文件可删除该文件。删除非空文件夹前必须确认，根目录的 `README.md` 不允许删除。

## 通过 Agent 使用

当对话需要读取或维护知识库时再激活 `/knowledge`。Agent 可以：

- 列出当前组织中的资料包；
- 将资料包载入当前 Chat 工作空间；
- 先阅读 `README.md`，再逐步列出和打开相关文件，仅在有帮助时使用 bash 搜索；
- 在本地整理新的资料包并发布；
- 将完整资料包发布为新的版本；
- 仅在用户明确要求时删除资料包。

Agent 的内置命令负责在平台存储与 Chat 沙盒之间同步完整资料包。Agent 使用普通文件系统工具读取、搜索、编辑和调整本地文件结构，避免 Knowledge 集成重复实现一套文件操作能力。

发布会替换整个文件树并递增当前版本，本地资料包中不存在的文件会从远端移除。可传入 `--expected-version` 拒绝过期发布；未传入时并发发布按提交顺序保存，后一次提交覆盖前一次。发布前应重新获取最新资料包并合并修改，避免覆盖他人的更新。搜索索引异步构建，索引仍在处理或失败不代表需要重新上传已保存文件。

默认情况下，每次获取的资料包版本都会写入独立的带版本目录。这样，即使复用同一个工作空间，新版本中已经删除的文件也不会被误认为当前内容。

## 共享与归属

直接共享给当前账号的 Knowledge 资料包会显示在 Web 应用的“与我共享”中。共享只会授予资源级权限，不会改变资料包的所有者或来源。`/knowledge` 命令的资料包目录仍仅限于当前组织；如需访问其他所有者共享的资料包，请使用 Web 应用的共享视图。

## CLI 与版本元信息

命令为 `list/get/download/check/create/publish/delete`；文件检索使用 download + bash。
`list` 返回一页；使用 `--offset` 跟随 `next_offset` 直到 null，再用 `jq`/`grep` 筛选元信息。create/check/publish 必须指定 `--source-dir`。
README.md 顶部 YAML 元信息包含 name（1–200 字符）及 description（最多 2000 字符，可为空字符串）。
check 校验完整目录但不保存；publish 同时发布元信息与所有文件。
发布必须传入下载时的 `--expected-version`；版本过期或存在未发布草稿时拒绝写入，不修改任何内容。

网页名称、描述编辑也保存到 README 草稿，发布新版本后正式生效；保存必须携带草稿哈希。
下载的 README 包含包元信息；下载不改变远端已保存的版本。
历史详情从对应版本的 README 获取名称与描述。后台索引状态不影响文件发布成功与否，不应重复发布等待索引。

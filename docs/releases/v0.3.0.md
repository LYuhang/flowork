# v0.3.0 historical development notes

The old GitHub Release and its downloadable attachments are retired as part of
the Flowork rename. This page preserves the development history, not a current
download or deployment recommendation. See [installation](../installation.md)
and [rename compatibility](../flowork-rename.md) for current instructions.

Flowork v0.3.0 is an alpha release focused on making the complete path from an
idea to a reusable service practical: converse with an Agent, work with browser
and file context, build a Workflow, run it as a Task or Deployment, and preserve
the result as a document, diagram, or Knowledge package.

## Highlights

- **Codex-first conversations.** Connect a Codex account or compatible API,
  select a model and reasoning level in the composer, and safely resume the
  same Chat after a sandbox restart. A Chat stays within its selected provider,
  while later turns may switch to another compatible model from that provider.
- **OpenRouter connections.** Settings can connect an OpenRouter account and
  expose Responses-compatible models to Codex. Model metadata, source, Runtime,
  and reasoning selections are recorded per turn for continuity and diagnosis.
- **Sandbox-contained MCP tools.** Built-in MCP servers now run inside the
  isolated Agent sandbox. Slash commands activate only the capabilities needed
  for `/workflow`, `/task`, `/deployment`, `/knowledge`, `/diagram`, or
  `/document`.
- **File-oriented Knowledge.** A Knowledge item is a versioned folder with a
  root `README.md` and arbitrary nested files. The Web interface provides note
  cards, a familiar file tree, and content-focused previews; derived search
  indexes remain rebuildable rather than replacing the original files.
- **Professional artifacts and previews.** Chat file cards open a dedicated
  Preview experience for source code, Markdown, tables, Office documents, PDF,
  images, audio, video, draw.io diagrams, URLs, and explicit unsupported-format
  fallbacks. Diagram generation uses the official draw.io MCP through a thin
  Flowork integration.
- **Operational automation.** Workflows can become scheduled Tasks or callable
  API/Webhook Deployments. The Agent can collect paginated Task and Deployment
  diagnostics into JSON and JSONL files for later searching and incident
  analysis.
- **Browser automation.** The MV3 extension connects the Agent to the user's
  active browser context while keeping browser sign-in state separate from
  platform credentials.
- **Consistent product UX.** Navigation, detail layouts, logs, empty and error
  states, credentials, Passkeys, sharing, and English/Chinese copy now follow
  shared interaction and localization contracts.

## Upgrade notes

1. Back up PostgreSQL, object storage, and the deployment environment file.
2. Follow the current installation guide; retired release attachments are no
   longer a supported download source.
3. Run the normal deployment command. Database migrations are applied by the
   migration service before the API starts.
4. Reinstall the browser extension from the current application's Settings;
   extension and Web builds must come from the same source version.
5. Recheck Runtime accounts and API connections in Settings. OpenRouter models
   must support the Responses API to be offered to Codex.

Flowork is still alpha software. Review the security and deployment guidance,
use isolated test data for evaluation, and retain backups before upgrading.

# Workflow 画布第二阶段交互设计

本文记录 Flowork 画布第二阶段的设计与验收原则，供后续实现使用。核心约定是：节点入口新增父节点，节点出口新增子节点，只有连线中间执行插入；循环和并行成对创建并自动配对。本文为设计记录，不代表功能已经实现或通过验收。

## 范围

复用第一阶段的节点选择器、搜索、分类和最近使用，增加节点入口、出口及连线中间的上下文添加能力。底部 Add Node、画布右键等已有入口也必须遵守循环和并行成对创建的规则。

沿用现有 Workflow 数据结构、草稿、保存、版本冲突保护及撤销重做机制。

## 三种入口的固定含义

| 位置 | 操作 | 已有连接 |
| --- | --- | --- |
| 节点入口的加号 | 创建父节点，并连接到当前节点 | 保留，不重接 |
| 节点出口的加号 | 创建子节点，并从当前节点连接过去 | 保留，不重接 |
| 连线中间的加号 | 在指定连线上插入节点 | 将 A → B 替换为 A → 新节点 → B |

节点入口或出口的行为不能因已有连接而自动变为插入。连线插入只影响选中的连接，其他入线、出线不变。不提供隐式的“所有上游共同插入”或“所有下游共同插入”。

选择器显示当前位置，例如“为金额判断添加子节点”或“插入到读取资料与生成摘要之间”。取消选择或按 Esc 不产生节点、连线或占位配置。

## 加号显示与连接容量

加号仅在鼠标指针悬浮到对应入口、出口或连线操作区域时出现。单纯选中节点或连线不会让加号常驻。点击打开选择器后，保持触发位置可见，直到菜单关闭。

入口或出口达到允许的连接数量上限时，不显示对应加号。已有连接仍可通过连线中间的加号插入节点。

容量按节点类型、端口用途与图结构约束判断，不能把所有节点一律视为单入单出。按钮显示、选择器可选类型、拖线校验和实际提交必须遵守同一套规则。具体容量以引擎约束为依据，实现时需统一核对，不能仅凭当前前端允许拖线就判定合法。

只读画布和当前禁止编辑的状态不显示编辑加号。循环回线和配对辅助线不显示加号，它们不是普通执行连线。

## 各类节点的入口与出口

下表描述操作语义，所有入口均受连接容量与结构合法性约束；不允许新增连接的位置直接隐藏加号。

| 当前节点 | 入口加号 | 出口加号 |
| --- | --- | --- |
| Start | 永不显示 | 新增子节点 |
| End | 新增父节点 | 永不显示 |
| Prompt、Code、HTTPRequest、SubAgent、HumanApproval、Template、Transform、TableRead、TableWrite | 新增父节点 | 新增子节点 |
| Condition | 新增父节点 | 新增条件分支及其子节点 |
| LoopBegin | 在循环外新增父节点 | 在循环体入口新增子节点；入口已连接则隐藏 |
| LoopEnd | 在循环体末端新增父节点 | 在循环外新增子节点 |
| ParallelStart | 在并行结构外新增父节点 | 新增并行分支及其子节点 |
| ParallelEnd | 仅在可明确归属到合法分支时新增分支末端父节点 | 在汇合之后新增子节点 |

不能通过 LoopEnd 或 ParallelEnd 的入口创建没有合法上游路径的孤立节点，再将其伪装成完整循环或并行分支。如果当前位置无法形成合法结构，应隐藏入口加号；在已有分支末尾增加步骤使用该分支连线的插入加号。

## 条件分支

Condition 节点级出口加号表示新增一个条件分支及子节点，不能默认复用“其它情况”，也不能插入已有分支。

例如，现有条件 A 和其它情况分别连接节点 A、B。点击节点出口加号并选择 Code 后，增加“新条件 → Code”，原两条路径保持不变。

新增条件的表达式待填写，配置列表中位于“其它情况”之前；新建后打开相应配置并提示待配置。条件未补齐前不能被判定为可执行。

需要区分节点级出口和具体分支出口：

- 节点级出口加号创建新分支及子节点。
- 已存在但未连接的具体分支出口，可以添加该分支的子节点，填充其目标，不再新建分支。
- 具体分支已经连接后，该出口加号隐藏；在其连线上点击加号才是插入。

分支名称、表达式、顺序及目标必须与 Inspector 同步。插入现有分支时只替换目标，保留其他配置。

## 并行分支

ParallelStart 节点级出口加号表示新增并行分支及子节点。普通处理节点作为新分支时，自动形成 ParallelStart → 新节点 → 对应 ParallelEnd，原分支保持不变。

空分支的具体出口加号用于补齐该分支；已连接的分支出口隐藏加号。继续增加该分支中的步骤，使用分支连线中间的加号。

选择循环或并行时，以整个新结构作为分支，结构结束连接外层 ParallelEnd。选择 Condition 等具有多条后续路径的类型时，只能接好可明确确定的默认路径，其他待配置路径必须提示补齐，不能宣称已形成完整分支。

若既有 ParallelStart 缺少合法的结束配对，不得猜测汇合节点或跨结构连接。提示先完成配对。

## 循环和并行成对添加

选择器以“循环”和“并行”作为添加项目，一次创建开始与结束两个节点，不要求用户分开添加再手工设置 pair ID。所有添加入口使用相同规则。

| 结构 | 自动填写的配置 |
| --- | --- |
| 循环 | LoopBegin 的 loop_end_node_id 指向新 LoopEnd；LoopEnd 的 loop_begin_node_id 指回新 LoopBegin |
| 并行 | ParallelStart 的 parallel_end_node_id 指向新 ParallelEnd；ParallelEnd 的 parallel_start_node_id 指回新 ParallelStart |

新结构使用新分配的节点 ID，不能复用现有结构的配对节点。嵌套时保持内外配对独立。

不同入口按结构的开始和结束接线：

| 添加位置 | 接线方式 |
| --- | --- |
| 当前节点出口 | 当前节点 → 新结构开始 |
| 当前节点入口 | 新结构结束 → 当前节点 |
| A → B 的连线中间 | A → 新结构开始；新结构结束 → B，替换原连线 |
| 底部按钮或空白画布 | 创建配对结构，后续由用户连接外部节点 |

上述操作保留或替换连接的规则仍以“三种入口的固定含义”为准。分支上下文下，还需连接到对应汇合位置。

循环体、并行分支未补齐时，明确显示待配置状态，允许保存草稿，但不能误判为可执行。视觉占位不是执行节点，不新增虚构节点类型。

初始结构的建议交互是循环提供一个循环体添加位置，并行提供两个待配置分支。初始分支数量和占位样式属于实现细节；成对创建、自动配对及新增和插入的区别是必须遵守的原则。

## 插入类型与字段引用

普通处理节点支持在合法执行连线中插入。HumanApproval 与其他处理节点一致，不因审批具有通过和驳回结果而自动生成两个出口。

插入 Condition 时，由默认“其它情况”连接原下游，随后配置新的条件分支。插入循环或并行时，按完整配对结构接入。

Start 不出现在入口、出口或连线的上下文添加列表中。End 仅能添加到合法终点，不允许插入 A 与 B 之间，也不能用它代替循环或并行的结束边界。选择器需按当前结构筛选或禁用不合法类型，并提供原因。

控制流接线不等于数据字段映射。插入节点后，原下游引用的字段保持原样，不能自动把 A 的引用改成新节点输出。作用域或引用不合法时，由现有校验明确提示。

## 编辑一致性与布局

新增节点或配对结构、修改分支映射、接线及相关自动布局，作为一次完整编辑记录，一次撤销恢复全部变化。图结构修改必须原子提交，失败不能留下半套配对或残余连接。需要等待渲染测量的布局调整合并到对应编辑记录，不产生额外撤销步骤。

插入现有 Condition 或 ParallelStart 分支时，必须直接保留分支配置并替换目标，不能复用会删除分支配置的“断线再重连”逻辑。

菜单打开后，提交前再次确认源节点、目标节点、分支、连线、容量和可编辑状态仍有效。如果 Agent 修改或版本更新使上下文失效，应提示重新选择，不自动连接到其他位置。

沿用现有草稿和保存流程；结构修改使旧执行结果或失败续跑资格失效时，遵守现有规则，不能将旧结果显示成新结构的执行结果。

## 修改后的自动布局

Workflow 修改后，画布必须自动检查并调整布局，保证新增或变化的节点不会遮盖其他节点。用户无需手动点击 Auto Layout。该要求同时覆盖画布手动编辑、Agent 修改以及当前正在查看的版本更新后加载的新内容。

新增、删除、插入节点，新增分支，循环或并行成对创建、配对修改，以及连接关系变化，均触发布局计算。配置、名称等修改导致节点显示尺寸变化时，也应重新检查间距。批量修改完成后统一计算，不逐条操作反复重排。

优先调整受影响区域并保留其他节点的相对位置；局部调整不足以消除遮挡时，自动扩大布局范围，必要时重新排列整张图。不能为了保留旧坐标而留下重叠。布局保持流程方向、分支层次以及循环和并行的嵌套关系，并留出节点与分支之间的间距。

布局基于节点实际渲染尺寸，包含输出预览、错误信息和人工审批区域，不能只计算节点卡片。首次渲染或异步内容展开后，尺寸变化时再次消除遮挡；合并连续尺寸变化，避免布局抖动和无限触发。

自动布局保持当前缩放比例，优先保持正在操作或选中的节点在屏幕上的位置。必要时最小平移使新增内容可见，不自动 Fit View 或突然跳到整图中心。新增后选中节点并打开属性面板，配对结构默认选中开始节点。

手动拖动期间不抢夺节点位置；拖动结束后检查遮挡，必要时自动避让。撤销、重做恢复与该次编辑一致的布局。布局结果需保持稳定，相同图结构与尺寸不能不断产生不同位置。

可编辑草稿的节点坐标沿用现有保存方式，保存重开后仍能正确展示。只读或历史执行画布的布局调整仅影响展示，不改写历史 Workflow，也不自动创建版本。Agent 更新引发的布局只处理已经安全加载的新内容，不能绕过版本冲突保护覆盖本地未保存修改。

## 验收要求

实现完成后必须部署到真实服务验收，并记录结果；文档检查或单元测试不能替代实机验收。

- 验证所有节点类型的入口、出口、连线添加规则及不合法类型限制。
- 验证出口新增子节点保留所有原连线，入口新增父节点不重接原上游，只有连线操作执行插入。
- 验证加号仅悬浮出现，满连接隐藏，菜单打开期间操作稳定。
- 验证 Condition 出口创建新分支，原表达式、顺序和其它情况不变；分支插入保留原配置。
- 验证 ParallelStart 出口新增分支并正确汇合，不改变原分支。
- 验证循环和并行从各入口成对创建、双方 pair ID 正确、嵌套配对不串联，草稿占位不成为执行节点。
- 验证循环体、并行分支内部及边界附近的插入，不破坏作用域、配对及字段引用规则。
- 验证多入多出时仅修改指定连接；不出现孤立分支、自环、普通执行环或非法跨结构连接。
- 验证取消、撤销、重做、保存重开及菜单打开期间版本变化。
- 验证只读页面、编辑限制、中英文展示、节点结果展开时的布局和视角稳定性。
- 验证手动新增、插入、成对创建、分支修改及 Agent 批量修改后自动布局生效，无需手动点击 Auto Layout，节点及其输出、错误、审批区域均不遮盖。
- 验证局部空间不足时自动扩大布局范围，嵌套循环与并行仍清晰；异步内容尺寸变化后可再次避让，无持续抖动。
- 验证自动布局保持缩放和操作位置，拖动期间不抢位置，撤销重做及保存重开一致；只读布局不修改历史数据、不产生新版本，Agent 更新不覆盖本地未保存修改。
- 在真实服务执行普通、条件、循环、并行、嵌套和人工审批样例，核对实际路径与输出；待配置结构必须被正确拦截。

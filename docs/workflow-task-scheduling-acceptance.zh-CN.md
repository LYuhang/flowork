# Workflow 与 Task 定时执行验收记录

日期：2026-10-03。需求：[Workflow 与 Task 定时执行设计](workflow-task-scheduling-design.zh-CN.md)。

本次实现范围是共享定时任务入口、一次性固定时间任务、允许重叠的周期任务及执行隔离。关联文档中的画布入口/出口加号、连线插入等第二阶段画布设计不属于本次实现。

## 部署

代码部署到 `/opt/flowork`，在 `https://flowork.top` 使用测试账号操作。迁移 157 在现有数据库上升级成功，统一采用新调度规则；前端为生产构建。部署前备份数据库及源文件，安装后核对运行文件和前端入口的 SHA-256 与工作区/构建一致。

沿用现有 PostgreSQL、后台队列和沙盒服务，未增加额外组件或安装依赖。测试并发期间暂将 interactive 队列从 1 改为 2，结束后恢复为 1；不是压测。

## 实机验收

| 项目 | 操作与观察 | 证据文件 |
| --- | --- | --- |
| 两个创建入口一致 | Workflow、Task 各创建 once、cron、interval；六条任务实际触发并完成，版本固定，结果一致 | `scheduling-browser-results.json` |
| 一次性成功与过期保护 | 只触发一次，完成后 next run 为空，保留执行结果/Trace；恢复已触发或过期的一次性计划被拒绝，暂停期间到期不执行 | `scheduling-once-overlap-live.json`（前两个用例） |
| 一次性失败与时区 | CodeNode 实际抛错，失败记录与 Trace 保留且不重跑；带 +08:00 的时间精确转换，拒绝无时区时间 | `scheduling-failure-batch-live.json` |
| 历史与草稿版本 | 历史画布绑定对应确切版本；草稿先保存再创建；创建失败保留输入，重试不多生成版本；真实并发提交触发 409，阻止任务创建 | `scheduling-versions-browser-results.json` |
| 表单边界 | 面板中切换版本清空旧输入并提示；拒绝过去时间；明确拒绝 DST 不存在与重复时间；日历年/月/日及 24 小时时/分/秒可编辑确认；底部提交按钮固定可见 | `scheduling-edges-browser-results.json` |
| 跨时区显示 | 浏览器为 UTC，选择 Asia/Shanghai 的 17:42:03；提交为 09:42:03Z，创建成功摘要及 Task 配置均显示计划时区的时间并保留秒 | `scheduling-timezone-browser-results.json` |
| 审批并发与排队 | 两次执行同时等待各自审批，第三次排队；排队无 Trace/运行日志；暂停不影响已派发执行；批准、驳回、取消相互隔离；间隔按计划时间推进 | `scheduling-parallel-live.json` |
| 排队取消 | 手动重复触发产生独立 execution；取消尚未启动的一次执行后无运行日志/Trace，另一次审批和执行继续正常完成 | `scheduling-queue-cancel-live.json` |
| 普通长耗时执行 | 单次代码耗时 7 秒、计划间隔 4 秒，生成两个独立执行，后一次排队后成功；计划时间间隔仍为 4 秒 | `scheduling-slow-live.json` |
| 并发错误与乱序结束 | 同一任务的输入快照独立；一条审批超时、一条代码失败时，较早的慢执行继续运行；慢执行晚成功不覆盖较新执行的失败摘要 | `scheduling-concurrent-errors-live.json` |
| 批量任务回归 | 原有 batch 提交、实际执行、结果和日志正常 | `scheduling-failure-batch-live.json` |
| CLI 与说明 | 安装后的 create 帮助包含互斥的 --run-at / --interval / --cron；命令校验、Host 请求转换及查询契约回归通过；运行代码和 Agent 说明不再保留旧跳过规则 | `scheduling-cli-create-help.txt` 及自动化测试 |

原始证据及截图在服务器 `/root/flowork-human-approval-qa/` 中；不提交账号、会话、进程环境、数据库备份或原始服务日志。

“保存后创建失败”通过在真实浏览器中注入一次创建请求 503 验证表单保留；保存、重试成功请求和版本冲突请求均调用真实服务。其余表中执行结果来自部署服务实际运行，而非接口模拟。任务概览与执行记录通过独立事务更新，验收等待概览刷新后核对最终汇总。

## 自动化验证

- 后端相关测试 130 项通过：一次性触发、重复调度去重、间隔规则、任务状态汇总、结果隔离、CLI、日志分页及 worker 丢失处理。
- 人工审批的真实 RPC/数据库测试 6 项通过：通过、驳回、超时、执行取消、Trace 取消、进程丢失。使用隔离测试数据库和服务账号可访问的测试源码。
- 前端相关测试 38 项通过：任务列表/详情、日历交互、时区转换及 DST 边界。
- TypeScript、生产构建、部署路径检查、diff 空白检查通过。
- 日志分页测试将目标执行的日志夹在超过一页的其他执行日志中，覆盖升序/降序与后续游标，确认不会因先截断再过滤而漏查。

## 结果

需求实现和上述验收完成。调度暂停只影响未来派发，容量不足时保留排队执行；不会因上一次仍活跃而跳过。Task 仅管理计划及执行汇总，结果、错误、日志和 Trace 按 execution 隔离查询。

## 2026-10-03：通知配置与关联任务列表

已部署到真实服务并完成浏览器及 API 验收：

- Workflow 工具栏仅保留执行按钮，Run / Batch / Schedule 在 Inspector 中切换。
- 批量和定时任务共用成功／失败通知选项；任选一项显示单个 Email 输入框，全取消后隐藏。非法邮箱被 API 拒绝，合法配置随任务保存。
- 从 Workflow 页面实际提交批量任务和定时任务，确认成功执行；另使用会报错的 Workflow 验证批量样本失败及定时执行失败。发送函数保持 `pass`；定时执行命中通知策略时为 `skipped / delivery_not_implemented`，不产生虚假的排队／已发送状态。
- 两种 Inspector 关联任务列表支持完整 ID 复制、详情链接和实际绑定版本展示；验证同一 Workflow 的不同版本任务可共同列出。
- 真实点击详情链接到达对应任务；从 Inspector 跳到任务中心保留 Workflow 筛选，页面下拉筛选也可用；状态统计遵循 Workflow 范围。
- 实机发现并修正历史画布的批量提交会跟随主版本最新内容的问题：干净画布使用具体 `baseVersion`，保存修改后使用提交返回的版本。再次实测 `v1.sv1` 画布提交后任务准确绑定 `v1.sv1`。

自动检查：后端 48 项、前端相关用例 56 项通过；TypeScript 类型检查和生产构建通过。浏览器验收未出现页面脚本错误。测试证据和截图保存在服务器私有验收目录，账号凭据未写入仓库。
